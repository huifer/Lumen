## 1. 技术栈总览

| 层 | 技术 | 版本 | 说明 |
| --- | --- | --- | --- |
| 前端 | Next.js (App Router) + React + TypeScript | 15.5.28 / 19 | 无 UI 库，纯手写 CSS（`globals.css`） |
| 前后端连接 | Next.js rewrites | — | `/api/*` 代理到后端，前端代码零跨域配置 |
| 后端 | Python + FastAPI + uvicorn | 3.10 / fastapi 0.13x | 同步接口（demo 体量下够用） |
| AI | LangChain + `langchain-google-genai` | 4.x | `ChatGoogleGenerativeAI` + `GoogleGenerativeAIEmbeddings` |
| 向量存储 | numpy 稠密向量（本地文件） | — | 暴力余弦遍历，万级以下够用 |
| OCR | tesseract CLI（子进程） | 5.x | 中文需 `chi_sim` 语言包 |
| 图像处理 | Pillow | 12.x | 主色提取、缩略图、截图判定、JPEG 重编码 |

**设计原则**：单文件单一职责，模块间只通过数据结构（`FileRecord`）通信；所有"可能失败"的 AI 调用都有降级路径，保证 demo 永远能跑出结果。

## 2. 架构与数据流

```
浏览器
  │  http://127.0.0.1:3000
  ▼
Next.js 前端 (app/, components/)
  │  fetch('/api/...')                    ← 同源请求，无 CORS
  │  next.config.mjs rewrites 代理
  ▼
FastAPI 后端 (lumen/server.py, :8000)
  │
  ├─ POST /api/build ──▶ pipeline.build()
  │      ① ingest.scan()          扫描目录 → [FileRecord]（纯本地 IO）
  │      ② understander.understand()  并发(3线程)调用 Gemini / 离线兜底
  │      ③ embedder.transform_many()  文本 → 向量（Gemini / 离线 hashing TF-IDF）
  │      ④ index_store.save()     records + vectors + idf 落盘
  │
  └─ POST /api/search ─▶ pipeline.search()
         q_vec = embed(查询)
         hits  = cosine(索引向量) + keyword_bonus（字面命中加权）
         排序取 TopK
```

**关键认知：三个"配置源"决定了后端行为**

1. `backend/.env` → `config.py` 读入（`GEMINI_API_KEY`、模型名、OCR 配置）
2. `ListModels` API → `models.py` 启动时发现该 Key 真正可用的模型（带 10 分钟缓存）
3. UI 传入的 `backend` / `model` / `embed_model` 参数 → 覆盖默认值

### 模块间唯一的数据契约：`FileRecord`

`ingest.py` 定义，全链路传递，`to_dict()` 直接序列化进 index.json：

```python
@dataclass
class FileRecord:
    path / rel_path / name / ext / kind      # 身份信息（kind: image|pdf|doc|text|other）
    size / mtime / width / height            # 元数据
    dominant / dominant_color_name / dominant_ratio / is_screenshot   # 视觉特征
    text                                     # 文本类文件正文片段（≤8000 字符）
    title / description / tags / ocr_text    # 理解阶段填充
```

**加字段就改这一处**（+ pipeline 的 `_file_summary` + 前端 types.ts），这是全项目最重要的扩展点。

## 4. 核心流程详解

### 4.1 build（`pipeline.build` → `_build_once`）

```python
def build(root, backend=None, store=None, gen_model=None, embed_model=None):
    try:
        return _build_once(root, backend, store, gen_model, embed_model)
    except Exception as exc:
        if backend == "offline":
            raise
        # Gemini 整体失败 → 降级离线重建，返回带 warning 的结果
        result = _build_once(root, "offline", store, None, None)
        result["degraded"] = True
        result["warning"] = redact(f"Gemini 后端不可用，已自动降级为离线模式：{exc}")
        return result
```

`_build_once` 四步：

1. **理解**（并发）：`ThreadPoolExecutor(max_workers=3)`。每个文件的流程：
   - 查缓存 `cache.get(rec, model)` → 命中直接返回（**0 次 API**）
   - 未命中 → 按候选模型链逐个尝试 → 成功后 `cache.put()`
2. **向量化**：`texts = [searchable_text(rec) for rec in records]`，
   `searchable_text = title + description + tags + ocr_text + text[:2000] + 主色名` —— **检索质量的核心**。
   离线 embedder 需要先 `fit(texts)` 算 IDF；Gemini 直接批量。
3. **落盘**：`store.clear()` 后逐条 `add(rec, vec)`，最后 `save()`（json + npy + idf）。
4. **返回统计**：`models_used`（各模型调用次数）、`quota_exhausted`、`cache_entries` —— 直接透传给前端展示。

### 4.2 search（`pipeline.search`）

```python
final_score = cosine(查询向量, 文档向量) + keyword_bonus
# keyword_bonus = 0.05 * (命中token数/查询token数) * 4  →  最高 +0.20
```

- 查询向量与索引向量用**同一个模型**生成（`store.meta["embedder"]["model"]` 记录了建索引时的模型，search 时强制复用，防止维度不一致）。
- 维度不一致时返回业务错误「请重新构建索引」，而不是 500。
- 离线模式：用 `store.meta["embedder"]` 里的 idf 表重建 `OfflineEmbedder`，保证查询与文档用同一套词权重。

### 4.3 理解的双后端设计（`understand.py`）

```
GeminiUnderstander                        OfflineUnderstander
├─ 候选模型链（配额耗尽自动切换）            ├─ 图片：主色+尺寸+截图判定+tesseract OCR
├─ with_structured_output(SCHEMA)          ├─ 文档：前两句+2-gram 关键词
├─ SystemMessage 强制中文                   └─ 永不联网，永不抛异常
├─ _retry()：只重试 SSL/超时/5xx
└─ 429 → 标记该模型 → 换下一个候选
两者失败 → 返回离线结果 + "（Gemini 调用失败，已回退离线理解）" 后缀
```

**为什么 429 不重试？** 免费档 429 的 `retryDelay` 是 ~22 小时，重试只会继续 429。
**为什么缓存键不含模型名？** 换模型重建时能复用旧结果，避免为同一文件重复烧配额。

### 4.4 模型发现（`models.py`）

- `list_models(api_key)`：`GET /v1beta/models` → 按 `supportedGenerationMethods` 分成 generation / embedding 两组，缓存 10 分钟。
- `resolve_generation_model()`：`.env` 显式指定 > 候选偏好列表（3.6-flash → 3.5-flash-lite → 3.1-flash-lite → 3.8-flash …）> 兜底常量。
- `candidate_generation_models()`：生成**有序候选链**（首选 + 偏好列表 + 其余 flash 系按版本号倒序），供理解阶段 429 时逐个切换。
- `_pick()` 的兜底逻辑：偏好全不可用时，从可用列表里挑版本号最高的 flash 模型。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/thumb?path=<绝对路径>` | 缩略图（480px JPEG）。**仅索引内文件**，否则 403；不可读 415 |

## 6. 磁盘数据格式

### index.json

```jsonc
{
  "meta": {
    "backend": "gemini", "understander": "gemini",
    "understand_model": "gemini-3.5-flash-lite",
    "root": "/abs/scan/root", "built_at": "2026-10-28 16:10:00", "count": 8,
    "embedder": {"model": "gemini-embedding-2", "dim": 1536}   // search 时复用
  },
  "records": [ { /* FileRecord.to_dict() × N，顺序与 vectors 行一一对应 */ } ]
}
```

### understand_cache.json

```jsonc
{
  "<sha1(path|mtime|size)>": {
    "path": "/abs/file.png", "model": "gemini-3.5-flash-lite",
    "at": "2026-10-28 16:09:00",
    "description": "...", "tags": [...], "ocr_text": "..."
  }
}
```

> 注意：vectors.npy 的行序 = records 的顺序 = index_store.add 的调用顺序。任何改变记录顺序的改动都必须重建索引（或同步改 store 的对齐逻辑）。

## 7. Gemini 接入细节与免费档约束

### 7.1 免费档的真实约束（2026-10 实测）

| 事实 | 对代码的影响 |
| --- | --- |
| 配额按 **模型** 计：每模型 ~20 次/天（`GenerateRequestsPerDayPerProjectPerModel-FreeTier`） | 429 时换候选模型即可继续（`understand.py` 的候选链） |
| 多个 Key 属于同一项目 → 共享配额 | 加 Key 数量没用，加模型种类才有用 |
| 429 的 retryDelay ≈ 22h | **禁止重试 429**；只重试 SSL/超时/5xx（≤3 次） |
| embedding 配额独立且宽松 | 向量化不需要特殊处理 |
| 并发+重试会快速烧穿配额 | 并发限 3；缓存兜底 |

### 7.2 LangChain 用法要点（踩过的坑）

```python
# ① 图片：必须用 OpenAI 兼容的嵌套格式，扁平写法会 KeyError: 'image_url'
{"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}}
# 等价替代：{"type": "media", "mime_type": "image/jpeg", "data": <bytes>}

# ② 结构化输出：传 dict schema 即可，返回的就是解析好的 dict
llm.with_structured_output(IMAGE_SCHEMA).invoke([SystemMessage(...), HumanMessage(...)])

# ③ Gemini 3.x 固定采样参数：传 temperature 会被忽略并告警 → 不传

# ④ Gemini 3.x 默认会输出英文 → SystemMessage 强制中文（SYSTEM_PROMPT）

# ⑤ 图片统一转 JPEG 再 base64（bmp/tiff 不被接受；also 减小体积）
image_as_jpeg_base64(path)   # understand.py

# ⑥ Embeddings：gemini-embedding-001 支持 768/1536/3072 维；task_type 区分文档/查询
GoogleGenerativeAIEmbeddings(model="models/gemini-embedding-2",
                             google_api_key=KEY,
                             task_type="RETRIEVAL_DOCUMENT",   # 查询侧用 RETRIEVAL_QUERY
                             output_dimensionality=1536)
```

### 7.3 模型名会过期

`text-embedding-004`（2026-01 停用）、`gemini-2.0-flash`（2026-06 停用）。
所以**永不写死**：`ListModels` 运行时发现 + 偏好列表 + 兜底常量三层。当前实测可用组合：

| 用途 | 首选 | 备选 |
| --- | --- | --- |
| 理解 | `gemini-3.6-flash`（6~7s/图，稳） | `gemini-3.5-flash-lite`（5s/图）、`gemini-3.1-flash-lite`、`gemini-3.8-flash`（短期可用、波动大） |
| 向量 | `gemini-embedding-2`（多模态，1536/3072 维） | `gemini-embedding-001`（纯文本 GA） |

## 8. 常见二次开发任务（怎么做）

### 8.1 支持新的文件类型（例：`.rst`、`.ppt`）

1. `config.py`：把扩展名加进 `TEXT_EXT` / `DOC_EXT` / `IMAGE_EXT`
2. 文本类 → 完事（`ingest.extract_meta` 会直接读文本）
3. OOXML 类（pptx/docx/xlsx）→ `ingest.extract_ooxml_text` 里加一条 name 过滤规则
4. 二进制类（如 pdf 正文）→ 在 `extract_meta` 加分支，把文本塞进 `meta["text"]`
5. 重新构建索引

### 8.2 改 AI 的描述风格 / 提示词

全部集中在 `understand.py` 顶部：`IMAGE_SCHEMA`、`DOC_SCHEMA`、`SYSTEM_PROMPT`，以及 `_image` / `_document` 里的 prompt 文本。改完**删除该文件的缓存**（或 `rm data/understand_cache.json`）再重建，否则会命中旧缓存。

### 8.3 换/加生成模型

- 临时：UI 下拉框选择，或 `POST /api/build` 带 `model` 字段
- 永久默认：`config.py` 的 `GEMINI_MODEL` / `GEMINI_EMBED_MODEL`（或 .env）
- 候选链顺序：`models.py` 的 `PREFERRED_GEN_MODELS`

### 8.4 换向量方案（Chroma / FAISS）

只需替换两处，接口不变：

- 写入：`pipeline._build_once` 第 3 步（现在是 `IndexStore.add/save`）
- 查询：`pipeline.search`（现在是 `store.vectors @ q_vec`）

建议实现成与 `IndexStore` 同签名的类（`add/save/load/clear/__len__` + `top_k(vec, k)`），在 `pipeline` 里按配置选择。注意保留 `records` 与向量的对齐关系。

### 8.5 增量索引（只处理新增/变更文件）

缓存已经是按 `path+mtime+size` 键的，天然支持——增量 = scan 后先查 index.json 里已有的记录，跳过"缓存命中且 mtime/size 未变"的文件，只理解新增的。改动点在 `_build_once` 第 1 步：加载旧 store，diff 出新集合。

### 8.6 加并行度 / 限流

`_build_once` 的 `ThreadPoolExecutor(max_workers=3)`。注意免费档 RPM 也有限，加大并发前先确认限流窗口；更好的做法是加一个简单的令牌桶（`time.sleep` 节流即可）。

### 8.7 加新 API 端点

`server.py` 里照葫芦画瓢：

```python
class XxxRequest(BaseModel):
    ...

@app.post("/api/xxx")
def xxx(req: XxxRequest) -> dict:
    ...
```

注意：任何可能包含路径/异常的返回值，过一遍 `redact()`。

## 9. 前端结构与修改指南

### 数据流

```
Explorer.tsx ('use client')
  useEffect        → api.health()      → health 状态（backend/model 列表/已索引数）
  handleBuild      → api.build(...)    → buildResult + 刷新 health
  handleSearch     → api.search(...)   → result.hits → 渲染 ResultCard 列表
  useSearchParams  → ?q=xxx 首次进入自动搜索（page.tsx 用 <Suspense> 包裹 Explorer）
  router.replace   → 搜索成功后把 ?q= 写回地址栏（可分享）
```

### 改 UI 的常见位置

| 想改什么 | 文件 |
| --- | --- |
| 标题/文案 | `app/page.tsx`（hero 区） |
| 颜色/圆角/间距 | `app/globals.css` 顶部的 `:root` CSS 变量 |
| 示例查询按钮 | `Explorer.tsx` 的 `EXAMPLES` 常量 |
| 结果卡片布局 | `components/ResultCard.tsx` |
| 加字段展示（如 mtime） | `ResultCard.tsx` + `lib/types.ts` 的 `Hit` |

### 注意事项

- `Explorer.tsx` 是唯一需要 `'use client'` 的组件；`page.tsx` 保持 Server Component
- 图片用原生 `<img>`（缩略图是动态接口，不适合 next/image 优化），已加 eslint-disable
- 列表渲染必须带 `key`（现在用 `hit.path`）
- 条件渲染用三元而不是 `&&`（项目约定）
- 类型改动：后端返回变了 → 先改 `lib/types.ts`，`npx tsc --noEmit` 会帮你找全所有需要跟改的位置

### 调试思路

1. **搜索质量差** → 先看 index.json 里该文件的 `description/tags/ocr_text` 是否符合预期；

## 11. 已知限制与 Roadmap

| 现状 | 影响 | 计划方向 |
| --- | --- | --- |
| 全量索引，无增量 | 大目录重复构建浪费时间（缓存已兜住 API 成本） | scan 后与旧 index diff，只处理变更（见 8.5） |
| numpy 暴力余弦 | 万级文件检索变慢（秒级） | 换 Chroma/FAISS（见 8.4） |
| PDF 不解析正文 | pdf 只有文件名可搜 | pypdf 抽文本塞进 `FileRecord.text` |
| 同步接口 | 大目录 build 占住请求 | 改后台任务 + 轮询 `/api/build/status` |
| 图片重编码 JPEG | OCR 细节轻微损失 | `media_resolution` / 原图上传（注意配额） |
| 单机单用户 | — | demo 定位，暂无多用户计划 |
